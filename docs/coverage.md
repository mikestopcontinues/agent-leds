## The table

Each cell is the phase the signal moves to; `·` means no rule, so the signal changes nothing. A cell that names its own row's phase holds the session there against the signals ranked after it; alone it changes nothing, but a turn that ends again is announced again.

Columns: Start (Started), Prompt (Prompted), Perm (PermissionAsked), Quest (QuestionAsked), Answ (Answered), End (TurnEnded), End? (TurnEndedAsking), Fail (TurnFailed), Intr (Interrupted), Bg (Backgrounded), BgDone (BackgroundDone), Ended (Ended), Look (Looked), RdExp (ReadExpired), Aband (Abandoned), Dism (Dismissed).

One record can tell several signals, each a fact of its own. The first of them in this order with a rule from the session's phase is the move: Ended, Interrupted, TurnFailed, PermissionAsked, QuestionAsked, Answered, TurnEndedAsking, Backgrounded, BackgroundDone, TurnEnded, Prompted, Started, Dismissed, Abandoned, ReadExpired, Looked.

Signals of one family are told together by sound sessions:

- TurnEnded, TurnEndedAsking, Backgrounded, TurnFailed, Interrupted
- Prompted, PermissionAsked, QuestionAsked

Any other signals told together overlap: the order above still decides, and the daemon counts each set in `agent-leds status --json` and `agent-leds doctor`.

### Started

- Claude Code, file, observed: a session file naming a new pid or session, whose process started at its procStart; not a spare or a bg session (probe-claude cc0–cc11)
- Codex, file, observed: a thread's lock held, with a rollout whose session_meta is not a subagent's: neither its source nor its thread_source names one (probe-codex runA, runB, runD; desktop rollouts 0.162)
- Grok, file, observed: a new row in active_sessions.json whose process started at its pid_start, to the microsecond; a headless run and a subagent get none (probe-grok session_start, runs a, j)
- Cursor, hook, observed: beforeSubmitPrompt, run under a process Cursor marked running in .running with the second it started, the outermost of the marked processes in a row, so the CLI and not its node worker (probe-cursor runs A–I (markers, lsof); the bundle's install-in-use-marker; 0.5.0 hooks)
- Junie, file, inferred: a sidecar in processes/ that is the newest for its pid, whose process started no later than its startedAt; or a CurrentDirectoryUpdatedEvent naming a new folder (probe-junie session_start; Irrlicht pid.go)
- OpenCode, hook, observed: the plugin's busy, as a session that is not a subagent's goes busy, from the OpenCode process whose pid it names (probe-opencode T3–T16 (session.status busy, in serve and the TUI))
- Pi, hook, observed: session_start or agent_start from a Pi with a UI, naming its own pid, which is the hook's parent, and its session file (probe-pi ext084, ext152, extfork, extdir, extresume)

## Moves each harness cannot make

**PermissionAsked**: an approval wait shows as the light it interrupts.

- Grok: Idle, Working, Background, Asked, AskedRead, Stopped, StoppedRead, Failed → Blocked
- Cursor: Idle, Working, Asked, AskedRead, Stopped, StoppedRead, Failed → Blocked
- Pi: Idle, Working, Asked, AskedRead, Stopped, StoppedRead, Failed → Blocked

**QuestionAsked**: a question the agent waits on shows as the light it interrupts.

- Cursor: Idle, Working, Asked, AskedRead, Stopped, StoppedRead, Failed → Blocked

**Backgrounded**: a turn whose background work runs on shows as stopped while that work runs.

- Cursor: Idle, Working, Stopped, StoppedRead → Background
- Junie: Idle, Working, Stopped, StoppedRead → Background
- OpenCode: Idle, Working, Stopped, StoppedRead → Background
- Pi: Idle, Working, Stopped, StoppedRead → Background

## Phases never entered

Searched from `Gone` over the signals a harness declares and the daemon's own.

- Cursor: Background, Blocked
- Junie: Background
- OpenCode: Background
- Pi: Background

## Stuck phases

Phases with a light that a harness reaches but leaves only when its process ends or through the daemon's own signals. Each is a place where an experiment or a deliberate guess is worth considering.

No harness has a stuck phase.
